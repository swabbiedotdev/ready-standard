# Ready standard

The `.ready` standard writes a product's intent as a **Ready Intent Package
(RIP)**, or ready package: a `product/` directory of typed YAML records, one per product, module,
actor, capability, system, journey, step, surface, operation, sequence, rule,
constant, entity, entity group, state machine, quality constraint, term, and
acceptance exception. Records link to each other by id, so the package is a
graph that software can check and render: Ready Room draws every journey,
sequence, and data diagram from the records, and its validator checks every
reference.

```yaml
# product/notes/rules/length.ready
ready: 1
kind: rule
id: notes.rule.length
module: notes
title: A note fits NOTE_MAX_LENGTH
when: The note's text is longer than NOTE_MAX_LENGTH characters
then: The save is refused with too_long and the editor keeps the text
otherwise: The note is saved
constants:
  - notes.const.max-length
```

This repository is the home of the standard as [Ready Room](https://readyroom.dev)
uses it, and of the `ready-standard` agent skill for authoring and maintaining
`.ready` packages.

**The specification is [skills/ready-standard/references/format.md](skills/ready-standard/references/format.md).**
It lives inside the skill so an installed skill carries it; nothing else in
this repository restates it. Where it and Ready Room's schema
(`app/src/shared/intent/types.ts`) disagree, the schema wins and this
repository is out of date.

## Using a package

A repository with a ready package keeps it at `product/`, starting with
`product/product.ready`. To validate or export it you need a checkout of Ready
Room (Node 24+, `npm install` run once):

```sh
# from the Ready Room checkout
npm run ready -- validate <repo>              # must report 0 errors
npm run ready -- export <repo> <out>          # readable Markdown book with diagrams
npm run ready -- export <repo> <out>.json --format json
npm run ready -- schema                       # the JSON Schema for one record

# or from anywhere
npm --prefix <ready-room> run ready -- validate "$PWD"
```

`<repo>` is the directory that contains `product/`. A standalone CLI,
`@ready-standard/cli` with a `ready` binary, is planned so a repository can
validate without a Ready Room checkout; it is not built yet.

To start a package, copy
[skills/ready-standard/assets/template-package/product/](skills/ready-standard/assets/template-package/product/)
into the repository, rename the example module (`notes`), and replace the
values. Each template's comments list its kind's required and optional fields.
For editor completion, point your YAML language server at
`assets/ready.schema.json` for `*.ready` files.

## Installing the skill

The skill is a standard Claude Code skill folder. Copy or link
`skills/ready-standard/` to `~/.claude/skills/ready-standard/` (personal) or
`<repo>/.claude/skills/ready-standard/` (one project). It replaces the
`product-intent-manager` skill (written for Markdown Product Intent Packages,
PIPs) for ready packages: that skill's principles carry over, restated for
records in `references/principles.md`, and its Markdown and Mermaid file
conventions do not.

## Checking this repository

```sh
scripts/check.sh <ready-room-checkout>
```

It validates the template package (0 errors and 0 warnings required) and
confirms `assets/ready.schema.json` matches the schema Ready Room generates. See
[AGENTS.md](AGENTS.md) for the full sync procedure.
